# OtoMix

WEB会議の録音用に作った、軽量な音声録音アプリです。**マイク（自分の声）** と **システム音声（相手の声）** を、別のミキシングソフトなしで1つのファイル（MP3 / WAV）にまとめて録音します。Windows と Linux で動きます。

- 画面は1枚だけです。デバイスを2つ選び、保存先を決めて、録音ボタンを押します。
- どちらか片方だけ録りたいときは、**ミュートボタン**でその入力を無音にできます。録音中でも切り替えられます。
- 音の取得とミックスはアプリ内で行い、ffmpeg はエンコードだけを担当します。

## 必要なもの

| | Windows | Linux |
|---|---|---|
| ffmpeg | PATH 上に `ffmpeg` が必要 | PATH 上に `ffmpeg` が必要 |
| 音声 | Windows 標準（WASAPI） | PulseAudio または PipeWire(pulse互換)。`pactl` と `parec`（`pulseaudio-utils`）が必要 |

配布ビルドは .NET ランタイム込みの単一ファイルなので、.NET のインストールは要りません。

## 使い方

1. `OtoMix.exe`（Windows）または `OtoMix`（Linux）を起動します。
2. **マイク** と **スピーカー** を選びます。
   - スピーカーには、**会議アプリの音が出ている再生デバイス**を選んでください。そのデバイスに音が流れていないと、システム音声は無音で録音されます。
3. 保存先を確認します（`…` で変更できます）。拡張子が `.mp3` か `.wav` かで形式が決まります。
   - 既定は `~/Recordings/OtoMix_日時.mp3` です。
4. **録音開始** を押します。録音中は経過時間が表示されます。
5. **録音停止** を押すと保存されます。保存先は、次の録音で上書きしないよう新しい日時入りの名前に切り替わります。

### ミュート

各デバイスの右にあるボタンで、その入力を無音にして録音します（録音の長さは変わらず、その入力の部分だけが無音になります）。

- 録音の前でも途中でも切り替えられます。
- 両方をミュートしたままでは録音を始められません。

### 出力

| 拡張子 | 形式 |
|---|---|
| `.mp3` | MP3（libmp3lame、VBR品質2） |
| `.wav` | 16bit PCM |

どちらも 48kHz・ステレオです。

## ビルドと実行

.NET 8 SDK が必要です。

```bash
dotnet run --project src/OtoMix        # 開発実行
dotnet test                            # テスト
```

配布用の単一ファイル（ランタイム同梱、約90MB）を作るには:

```bash
dotnet publish src/OtoMix -c Release -r linux-x64 --self-contained \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist/linux-x64
dotnet publish src/OtoMix -c Release -r win-x64 --self-contained \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist/win-x64
```

## 仕組み

```
 マイク ──┐                                   ┌─ .mp3
          ├─ アプリ内でミックス ─ PCM ─ ffmpeg ─┤
 スピーカー ┘  （ミュート・無音の穴埋め）  (stdin)  └─ .wav
```

| | 取得 | デバイス一覧 |
|---|---|---|
| Windows | WASAPI（マイクはキャプチャ、スピーカーはループバック。NAudio） | WASAPI |
| Linux | `parec` | `pactl` |

- 取得した音を 48kHz・ステレオに揃えて足し合わせ、f32le の PCM として ffmpeg の標準入力へ流します。
- システム音声は再生が無いとデータが来ません。そのため実時間のクロックで一定量ずつ読み、足りない分は無音で埋めます。
- 停止は、ffmpeg の標準入力を閉じて、エンコードを仕上げさせてから終わらせます。5秒たっても終わらない場合だけ強制終了します。
- ミュートは入力ごとの音量をその場で0にする（10msのフェード付き）ので、押した瞬間に効きます。

Windows ではシステム音声に WASAPI ループバックを使うので、「ステレオ ミキサー」や仮想オーディオケーブルを入れる必要はありません。

## 既知の制限

- 録音開始の押下から実際に録音が始まるまで約1秒かかります。Linux では、取得の接続待ちで、ファイル先頭の約0.35秒が無音になります。
- Windows で3ch以上（5.1/7.1 など）の再生デバイスは、先頭2ch（L/R）だけを使います。
- Windows の描画はソフトウェア描画に固定しています。
- 録音中に使っているデバイスを抜いた場合の動作は、実機では確かめていません。
- 長時間録音でのマイクとシステム音声のずれは、測っていません。

## 動作確認の状況

- **Linux（WSL2 + WSLg）**：実ffmpegと実際の PulseAudio で、録音、停止、ミュート切替、エラー表示をテストしています。ミュートの遅れは約50ms（測定の細かさの限界）でした。
- **Windows 11 実機**：WASAPI によるデバイス列挙、マイクとシステム音声の同時録音、ミュートの切替を、アプリと同じ録音処理をGUIなしで動かす検証用ツールで確認しています（このリポジトリには含めていません）。
- **画面**：描画した画像で確認しています。実際のデスクトップにウィンドウを表示しての確認と、保存先ダイアログが実際に開くことの確認は、開発環境の制約でできていません。
- 実マイクで声を録った確認は、まだしていません（環境ノイズの録音までは確認済み）。
